# Восстановление кодов входа через Wappi

Операция `DOS Production Ops → configure-wappi` применяет актуальные реквизиты
без пересборки веб-приложений, APK или iOS. Она не отправляет сообщения.

1. В кабинете Wappi перевыпустить раскрытый API-токен и взять ID того же профиля.
2. В [GitHub Actions secrets](https://github.com/milaniumkz/dos-taxi/settings/secrets/actions)
   создать/обновить `WAPPI_TOKEN` (сам токен, без Bearer) и `WAPPI_PROFILE_ID`.
   Можно использовать секреты окружения production. Не передавать их через чат,
   workflow inputs, код, PR или публичные файлы.
3. Запустить `DOS Production Ops`, операция `configure-wappi`.
4. Запустить `sms-diagnostics`: ожидаются успешный ответ Wappi и наличие профиля.
5. Проверить доставку одного кода на согласованный номер владельца.

Реквизиты идут из secrets по зашифрованному SSH stdin. До записи операция делает
только HTTPS GET официального `/api/profile/all/get`, проверяет наличие нужного
профиля и статус OPEN. Ошибка токена/профиля или отсутствие secrets оставляет
runtime без изменений. Редиректы с заголовком Authorization запрещены.

При успехе сохраняется закрытая резервная копия `.env` на VPS (каталог 0700,
файл 0600), затем атомарно меняются только реквизиты Wappi и настройки реальной
отправки. JWT, база, Redis и остальные параметры сохраняются. Обход OTP,
отладочные коды и заглушка отправки выключены. Контейнер API пересоздаётся
с текущим образом: простой restart не перечитывает env_file. При провале readiness
восстанавливается исходный файл и повторно проверяется API. Используется общий
lock с production deployment.

Текущая интеграция Wappi использует WhatsApp. Для обычных SMS требуется отдельное
подключение SMSC; переключать провайдера без действующих реквизитов нельзя.
Ошибка `Token error` подтверждает отказ API в доступе, но не доказывает истечение
тарифа или отзыв токена: необходимо сверить пару токен/профиль с кабинетом.
