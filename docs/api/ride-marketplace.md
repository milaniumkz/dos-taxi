# Заявки с предложениями водителей — API v1

Новая схема действует для такси и межгорода во всех городах. Пассажир задаёт цену и выбирает предложение водителя. Создание заявки и предложение **не назначают водителя**. Классы автомобиля и действующие старые тарифы не участвуют в новой заявке.

Адрес API: `https://dos.89.126.200.51.sslip.io/api/v1`. Все запросы требуют `Authorization: Bearer <accessToken>`; используйте `Accept-Language: ru` или `kk`. Ответы ошибок — общий конверт `code`, `message`, `details`, `traceId`. Тексты новых ошибок доступны для изменения в админке, как остальные тексты ошибок.

## Настройки города

В админке откройте **Города → нужный город → Редактирование → Цена заявки**. Выберите **За место** (`seat`) либо **За весь салон** (`salon`) и сохраните. Валюта определяется настройкой города: KZT или RUB. Миграция ставит всем городам `seat`, минимальную сумму **всего заказа** 500 KZT, курс 7 KZT за RUB и шаг цены 50 KZT. В RUB минимум 71.43 и шаг 7.14. Валюта и старые суммы/балансы не изменяются.

В режиме `seat` количество 1–8 умножает цену одного места. Минимальная цена места округляется вверх, чтобы итог был не ниже минимума: например, 3 места × 167 KZT = 501 KZT. В `salon` множитель всегда 1; поле количества скрыто. Начальная комиссия города копируется из действующего городского тарифа (приоритет Economy и совпадающей валюты); при отсутствии тарифа используются значения города по умолчанию. Новые заказы фиксируют комиссию при создании.

`PATCH /admin/cities/{id}` принимает `ridePricingBasis`, `rideMinimumOrderKzt`, `rideExchangeRate`, `ridePriceStepKzt`, `rideCommissionPercent`. Изменения влияют на новые заявки. Уже созданная заявка сохраняет валюту, минимальную цену, шаг и комиссию. Финальная сумма выбранного предложения не пересчитывается по таксометру.

## Пассажир (роль client)

### 1. Получить условия цены

`POST /ride-requests/quote`

```json
{
  "serviceType": "taxi",
  "passengerCount": 2,
  "routePoints": [
    {"lat": 46.80123, "lng": 61.675111, "address": "станция Аральское море"},
    {"lat": 46.813356, "lng": 61.644856, "address": "Толе Би, 38"}
  ]
}
```

`serviceType` — `taxi` или `intercity`. Город определяется по точке подачи; допустим необязательный `cityId`. Ответ содержит `termsKey`, `cityId`, `cityName`, `currency`, `pricingBasis`, `passengerCount`, `minimumOrderPrice`, `minimumUnitPrice`, `priceStep`, `exchangeRate`, `commissionPercent`, `commissionFixed`. Для 2 мест в KZT минимальная цена одного места — `250.00`, всего — `500.00`. Ответ и условия должны быть получены заново при изменении адреса/количества.

### 2. Подать заявку

`POST /ride-requests`, обязательный `X-Idempotency-Key: <UUID>`.

```json
{
  "serviceType": "taxi",
  "passengerCount": 2,
  "routePoints": [
    {"lat": 46.80123, "lng": 61.675111, "address": "станция Аральское море"},
    {"lat": 46.813356, "lng": 61.644856, "address": "Толе Би, 38"}
  ],
  "termsKey": "<termsKey из quote>",
  "priceSteps": 1,
  "paymentMethod": "transfer_kaspi",
  "pickupEntrance": "2",
  "pickupComment": "Забрать у ворот",
  "needsChildSeat": true,
  "sharedRide": false
}
```

UI передаёт количество шагов кнопки (0–1000), а не сумму: `unitPrice = minimumUnitPrice + priceSteps × priceStep`. Здесь итог 2 × (250 + 50) = 600 KZT. В интерфейсе доступны `cash`, `transfer_kaspi`, `transfer_halyk`. Подъезд, отдельный комментарий, детское кресло и «Вместе» необязательны. «Вместе» — пожелание поездки, без автоматического поиска попутчиков.

Одинаковый ключ и тело возвращают ту же заявку. Другой запрос с тем же ключом — `409 IDEMPOTENCY_KEY_REUSED`; другая активная заявка — `409 ORDER_ALREADY_ACTIVE`. Изменённые городские условия — `409 RIDE_PRICING_CHANGED`: обновите quote. Ответ — обычный `OrderResponseDto` с `isNegotiated: true`, статусом `searching`, без исполнителя; заказ восстанавливается через `/orders/active`.

### 3. Получить предложения

`GET /ride-requests/{orderId}/offers`

Ответ `{order, items}`. Каждый элемент: `id`, `orderId`, `executorId`, `priceSteps`, `unitPrice`, `totalPrice`, `hasChildSeat`, `version`, `status`, `expiresAt`, `createdAt`, `updatedAt`, `driverName`, `driverRating`, `vehicleMake`, `vehicleModel`, `vehicleColor`, `vehiclePlate`. Возвращаются актуальные предложения доступных водителей; устаревшие, отозванные и недоступные предложения скрыты. Контактный телефон доступен через обычный заказ после выбора исполнителя.

Push `ride_price_offer` содержит `orderId`, `offerId`, `version`, `driverName`, `totalPrice`, `currency`. Отправка идёт через очередь push; версия предложения хранится в outbox и повторно отправляется при ошибке постановки в очередь. Доставка на телефон зависит от действующего device token и Firebase; получение актуального списка предложений выполняется также опросом API каждые 3 секунды, поэтому список не зависит от получения push.

### 4. Выбрать водителя

`POST /ride-requests/{orderId}/offers/{offerId}/accept`

```json
{"version": 1}
```

Передавайте версию именно показанного пассажиру предложения. Изменённая цена — `409 RIDE_OFFER_CHANGED`, истёкшее/отозванное предложение — `409 RIDE_OFFER_UNAVAILABLE`. Повтор выбора уже выбранного предложения идемпотентен. Блокировки заявки и исполнителя не допускают двух выбранных водителей или двух активных поездок у одного водителя (включая старое назначение и админку). После выбора остальные предложения закрываются. Дальше работают обычные endpoints статусов поездки, трекинга, отмены и оценки.

## Водитель (роль executor)

`GET /ride-requests/cities` возвращает активные города (`id`, `nameRu`, `nameKk`, `currency`). Для работы водитель должен быть подтверждён, на линии, иметь город в профиле и достаточный баланс. Вместимость автомобиля задаётся в `passengerCapacity` (1–8, по умолчанию 4); изменение вместимости/города, как изменение автомобиля, требует проверки.

### Лента

`GET /ride-requests/feed?lat=46.8&lng=61.67&limit=30&offset=0`

Ответ `{items, nextOffset}`. Порядок: расстояние по прямой до подачи, затем время создания и ID. Возвращаются только открытые заявки своего города, подходящие по вместимости. Элемент включает маршрут, валюту, оплату, цену места/салона, итог, минимум места, шаг, количество, подъезд, комментарий, пожелания, `pickupDistanceMeters` и `myOffer`. Лента занятого водителя пуста. `nextOffset` — следующая страница или `null`.

### Предложение / изменение цены

`POST /ride-requests/{orderId}/offers`

```json
{"priceSteps": 2, "hasChildSeat": true}
```

Для водителя шаги (-1000…1000) считаются от цены пассажира, а не от минимума. Сервер отклоняет цену ниже минимальной цены места/салона. Детское кресло требует явного подтверждения наличия. Один водитель имеет одно предложение на заявку: изменение увеличивает `version`; одинаковый повтор запроса не создаёт дубль. Предложение действует 300 секунд по умолчанию. Оно не назначает поездку — нужно дождаться выбора пассажира.

`POST /ride-requests/{orderId}/offers/withdraw` с пустым телом `{}` отзывает своё ожидающее предложение. Отзыв уже выбранного предложения не отменяет поездку: используется обычная отмена.

## Выпуск и откат

Флаг `FEATURE_RIDE_MARKETPLACE` включён по умолчанию; значение `false` приостанавливает новые endpoints, сохраняя старые поездки.

Сначала выпускаются API, миграция и админка; затем новые **пассажирское и водительское** приложения 1.1.0 (32). Старые API и заказы сохранены для переходного периода, поэтому старые версии продолжают старую схему. Новый интерфейс и лента требуют обновления мобильных приложений; сервер не может заменить установленный интерфейс.

Миграция добавляет поля, историю предложений и шаблоны уведомлений, не удаляет прежние тарифы/заказы/платежи. Откат приложения возможен на прежнюю версию с сохранением новой схемы БД. `migration:revert` намеренно запрещён, чтобы не уничтожить историю согласованных цен и предложений; изменения схемы после начала использования выполняются следующей миграцией.
