# Заявки с предложениями водителей — API v1

Новая схема действует для такси и межгорода во всех городах. Пассажир задаёт цену и выбирает предложение водителя. Создание заявки и предложение **не назначают водителя**. Классы автомобиля и действующие старые тарифы не участвуют в новой заявке.

Адрес API: `https://dos.89.126.200.51.sslip.io/api/v1`. Все запросы требуют `Authorization: Bearer <accessToken>`; используйте `Accept-Language: ru` или `kk`. Ответы ошибок — общий конверт `code`, `message`, `details`, `traceId`. Тексты новых ошибок доступны для изменения в админке, как остальные тексты ошибок.

## Настройки города

В админке откройте **Города → нужный город → Редактирование → Цена заявки**. Выберите **За место** (`seat`) либо **За весь салон** (`salon`) и сохраните. Валюта определяется настройкой города: KZT или RUB. Миграция ставит всем городам `seat`, базовый минимум 500 KZT, курс 7 KZT за RUB и шаг цены 50 KZT. В RUB минимум за место/салон 71.43 и шаг 7.14. Валюта и старые суммы/балансы не изменяются.

В режиме `seat` количество 1–8 умножает цену одного места. Минимальная цена одного места не уменьшается при добавлении пассажиров: 1 × 500 = 500 KZT, 2 × 500 = 1000 KZT, 3 × 500 = 1500 KZT. Выбранная кнопками цена места сохраняется при изменении количества. В `salon` множитель всегда 1; поле количества скрыто. Начальная комиссия города копируется из действующего городского тарифа (приоритет Economy и совпадающей валюты); при отсутствии тарифа используются значения города по умолчанию. Новые заказы фиксируют комиссию при создании.

`PATCH /admin/cities/{id}` принимает `ridePricingBasis`, `rideMinimumOrderKzt`, `rideExchangeRate`, `ridePriceStepKzt`, `rideCommissionPercent`. Изменения влияют на новые заявки. Уже созданная заявка сохраняет валюту, минимальную цену, шаг и комиссию. Финальная сумма выбранного предложения не пересчитывается по таксометру.

## Пассажир (роль client)

### 1. Получить условия цены

`POST /ride-requests/quote`

```json
{
  "serviceType": "taxi",
  "passengerCount": 2,
  "priceIsTotal": true,
  "routePoints": [
    {"lat": 46.80123, "lng": 61.675111, "address": "станция Аральское море"},
    {"lat": 46.813356, "lng": 61.644856, "address": "Толе Би, 38"}
  ]
}
```

`serviceType` — `taxi` или `intercity`. Город определяется по точке подачи; допустим необязательный `cityId`. Ответ содержит `termsKey`, `cityId`, `cityName`, `currency`, `pricingBasis`, `passengerCount`, `minimumOrderPrice`, `minimumUnitPrice`, `priceStep`, `exchangeRate`, `commissionPercent`, `commissionFixed`. Для 2 мест в KZT минимальная цена одного места — `500.00`, всего — `1000.00`. Ответ и условия должны быть получены заново при изменении адреса/количества.

### 2. Подать заявку

`POST /ride-requests`, обязательный `X-Idempotency-Key: <UUID>`.

```json
{
  "serviceType": "taxi",
  "passengerCount": 2,
  "priceIsTotal": true,
  "routePoints": [
    {"lat": 46.80123, "lng": 61.675111, "address": "станция Аральское море"},
    {"lat": 46.813356, "lng": 61.644856, "address": "Толе Би, 38"}
  ],
  "termsKey": "<termsKey из quote>",
  "priceSteps": 1,
  "paymentMethod": "transfer_kaspi",
  "pickupEntrance": "2",
  "pickupComment": "Забрать у ворот",
  "needsChildSeat": true,
  "sharedRide": false
}
```

Современный UI передаёт `priceIsTotal: true` и в quote, и при создании заявки. Сумма относится ко всей группе: 2 или 4 пассажира и `unitPrice: "500.00"` означают заказ за 500 KZT. Для выбора цены шагами используется `unitPrice = minimumUnitPrice + priceSteps × priceStep`, без умножения на количество пассажиров. Старые заявки и клиенты без флага сохраняют прежний расчёт. В интерфейсе доступны `cash`, `transfer_kaspi`, `transfer_halyk`, `transfer_psb` (ПСБ). Подъезд, отдельный комментарий, детское кресло и «Вместе» необязательны. «Вместе» — пожелание поездки, без автоматического поиска попутчиков.

Одинаковый ключ и тело возвращают ту же заявку. Другой запрос с тем же ключом — `409 IDEMPOTENCY_KEY_REUSED`; другая активная заявка — `409 ORDER_ALREADY_ACTIVE`. Изменённые городские условия — `409 RIDE_PRICING_CHANGED`: обновите quote. Ответ — обычный `OrderResponseDto` с `isNegotiated: true`, статусом `searching`, без исполнителя; заказ восстанавливается через `/orders/active`.

### 3. Получить предложения

`GET /ride-requests/{orderId}/offers`

Ответ `{order, items}`. Каждый элемент: `id`, `orderId`, `executorId`, `priceSteps`, `unitPrice`, `totalPrice`, `hasChildSeat`, `version`, `status`, `expiresAt`, `createdAt`, `updatedAt`, `driverName`, `driverRating`, `vehicleMake`, `vehicleModel`, `vehicleColor`, `vehiclePlate`. Возвращаются актуальные предложения доступных водителей; устаревшие, отозванные и недоступные предложения скрыты. Контактный телефон доступен через обычный заказ после выбора исполнителя.

Push `ride_price_offer` содержит `orderId`, `offerId`, `version`, `driverName`, `totalPrice`, `currency`. Отправка идёт через очередь push; версия предложения хранится в outbox и повторно отправляется при ошибке постановки в очередь. Доставка на телефон зависит от действующего device token и Firebase; получение актуального списка предложений выполняется также опросом API каждые 3 секунды, поэтому список не зависит от получения push.

### 4. Выбрать водителя

`POST /ride-requests/{orderId}/offers/{offerId}/accept`

```json
{"version": 1}
```

Передавайте версию именно показанного пассажиру предложения. Изменённая цена — `409 RIDE_OFFER_CHANGED`, истёкшее/отозванное предложение — `409 RIDE_OFFER_UNAVAILABLE`. Повтор выбора уже выбранного предложения идемпотентен. Блокировки заявки и исполнителя не допускают двух выбранных водителей или двух активных поездок у одного водителя (включая старое назначение и админку). После выбора остальные предложения закрываются. Дальше работают обычные endpoints статусов поездки, трекинга, отмены и оценки.

## Водитель (роль executor)

`GET /ride-requests/cities` возвращает активные города (`id`, `nameRu`, `nameKk`, `currency`). Для работы водитель должен быть подтверждён, на линии, иметь город в профиле и достаточный баланс. Вместимость автомобиля задаётся в `passengerCapacity` (1–8, по умолчанию 4); изменение вместимости/города сохраняет одобрение, а изменение данных автомобиля требует проверки.

### Лента

`GET /ride-requests/feed?lat=46.8&lng=61.67&limit=30&offset=0`

Ответ `{items, nextOffset, pendingOffer, serverTime}`. `pendingOffer` содержит текущее предложение водителя, включая `orderId`, `expiresAt`, `totalPrice` и `currency`, независимо от страницы списка. `serverTime` — время сервера, для корректного обратного отсчёта при отличающихся часах устройства. Порядок: расстояние по прямой до подачи, затем время создания и ID. Возвращаются только открытые заявки своего города, подходящие по вместимости. Элемент включает маршрут, валюту, оплату, цену места/салона, итог, минимум места, шаг, количество, подъезд, комментарий, пожелания, `pickupDistanceMeters` и `myOffer`. Лента занятого водителя пуста. `nextOffset` — следующая страница или `null`.

### Предложение / изменение цены

`POST /ride-requests/{orderId}/offers`

```json
{"priceSteps": 2, "hasChildSeat": true}
```

Для водителя шаги (-1000…1000) считаются от цены пассажира, а не от минимума. Сервер отклоняет цену ниже минимальной цены места/салона. Детское кресло требует явного подтверждения наличия. Один водитель имеет одно предложение на заявку: изменение увеличивает `version`; одинаковый повтор запроса не создаёт дубль. Предложение действует 30 секунд. У одного водителя может быть только одно действующее предложение на открытые заявки; до ответа пассажира, отзыва или истечения срока другое предложение не отправляется (`409 RIDE_OFFER_PENDING`). Оно не назначает поездку — нужно дождаться выбора пассажира.

`POST /ride-requests/{orderId}/offers/withdraw` с пустым телом `{}` отзывает своё ожидающее предложение. Отзыв уже выбранного предложения не отменяет поездку: используется обычная отмена.

## Выпуск и откат

Флаг `FEATURE_RIDE_MARKETPLACE` включён по умолчанию; значение `false` приостанавливает новые endpoints, сохраняя старые поездки.

Для тестирования выпускаются API, миграция, админка и две **веб-версии**: `/passenger/` и `/driver/`. APK и iOS-сборки в этот выпуск не входят. Старые API и заказы сохранены для переходного периода, поэтому старые версии продолжают старую схему. Новый интерфейс и лента требуют обновления мобильных приложений; сервер не может заменить установленный интерфейс.

Миграция добавляет поля, историю предложений и шаблоны уведомлений, не удаляет прежние тарифы/заказы/платежи. Откат приложения возможен на прежнюю версию с сохранением новой схемы БД. `migration:revert` намеренно запрещён, чтобы не уничтожить историю согласованных цен и предложений; изменения схемы после начала использования выполняются следующей миграцией.


## Ранее одобренные водители без города

Ранее созданные профили со статусом `verified` сохраняют одобрение. При открытии ленты сервер может заполнить отсутствующий город по сохранённой геопозиции водителя не старше пяти минут, используя тот же поиск активного города/зоны, что и для заявки. Это выполняется под блокировкой профиля и не подменяет уже выбранный город. Произвольный центр карты и устаревшая геопозиция для этого не используются.

Если город определить нельзя, `RIDE_DRIVER_CITY_REQUIRED` предлагает включить геолокацию или выбрать город в профиле; повторное одобрение администратора не требуется. Смена города и количества пассажирских мест сохраняет `verified` и текущий статус «На линии». Изменение личности/автомобиля по-прежнему требует проверки. Новые профили не одобряются автоматически, заблокированные пользователи не получают доступ. Для одобренного водителя вне линии используется отдельный код `RIDE_DRIVER_OFFLINE`.


## Компактная лента и ожидание

В видимой области ленты размещаются четыре компактные карточки, остальные доступны прокруткой. Маршрут, расстояние, места и итог видны сразу. Нажатие открывает подробности, комментарий, детское кресло и кнопки предложения цены. Условия бонусов доступны в раскрываемом блоке.

После подтверждённой отправки цены открывается недиспускаемый экран ожидания с суммой, отсчётом и кнопкой отзыва. Другие действия внутри приложения до завершения ожидания закрыты. Отзыв, истечение 30 секунд или выбор пассажира закрывают ожидание; при назначении открывается активная поездка. Восстановление ленты после перезагрузки также восстанавливает активное ожидание. ОС/браузер могут закрыть приложение; серверное время жизни предложения продолжает действовать независимо от клиента.

Миграция `0035` задаёт всем городам и новым записям срок 30 секунд, сокращает ещё ожидающие старые предложения до 30 секунд от последнего обновления. Принятые предложения и цены не меняются. Откат не продлевает действующие предложения.

### Passenger offer alerts

Passenger web polls invoke the same localized sound/notification path as foreground `ride_price_offer` push messages. `(orderId, offerId, version)` suppresses duplicate alerts from push and polling; revised prices produce a new alert. The driver feed initially loads history silently. The passenger offers screen also alerts for pending proposals on its first load, so opening or restoring the screen does not lose the arrival sound.

`POST /api/v1/notifications/devices` (Bearer JWT, 204) registers a device after notification permission is granted, without another OTP login. Body: `{"token":"<FCM token>","platform":"web"}`; supported platforms: `web`, `android`, `ios`. Identity and role always come from the JWT. The passenger offers screen has a bell control that requests permission, registers the token, and tests the sound. A granted permission is also registered automatically when reopening that screen. Push requires configured Firebase delivery and a browser/device token; website audio requires a user gesture. Background notification sound follows browser/OS settings.

Production Ops provides `passenger-offer-diagnostics` (counts/configuration presence only) and an explicitly invoked `seed-passenger-offers` preview. The latter refuses unless exactly one non-test, searching, negotiated request exists; it uses five clearly marked test drivers, sends normal API proposals five seconds apart, keeps the normal 30-second expiry, and takes those test drivers offline after expiry. It never assigns a driver or starts a trip.

Passenger offers use five compact cards per viewport; tapping a card opens its full vehicle details. Browser audio unlocks on user gestures; diagnostic sound-test buttons are not displayed. If an arrival is blocked before a user gesture, the presenter replays one pending alert on the next gesture within 30 seconds. Older pending sounds are discarded.

The passenger checkout keeps the route, compact seat/price steppers, optional entrance and selected payment visible. The total and submission button remain pinned below the form. Payment choices open in a sheet; optional comment, child-seat and Together preferences open under “Пожелания” / “Қосымша тілектер”. Dismissing a sheet preserves edited values. Count changes keep the chosen unit-price steps and recalculate the total. The normal RU/KK seat/salon form fits a 360×640 viewport without scrolling.

Пассажир оформляет такси и межгород на главной странице: выбор адресов сразу открывает встроенный расчёт, места, цену, подъезд, отдельный комментарий, пожелания и три способа оплаты. Переход на отдельный экран оформления не нужен; при редактировании маршрута введённые пожелания сохраняются. Для RU/KK проверено размещение всех элементов без прокрутки на 360×640 при обычном масштабе текста. Доставка сохраняет отдельный специализированный сценарий.

### Байконур: ручная цена и валюта по введённой сумме

Миграция `BaikonurManualPrice1710000000036` включает `cities.ride_manual_price_policy` только для Байконура / Байқоңыр. Остальные города сохраняют кнопки цены. Quote возвращает `manualPricePolicy: {"rubMinimum":"90.00","kztMinimum":"500.00","kztThreshold":"500.00"}`; деньги в коде UI не зашиты.

В Байконуре пассажир вводит цену цифрами за место (или салон при соответствующей настройке), вместо `priceSteps`. POST `/api/v1/ride-requests` принимает дополнительное строковое `unitPrice`, например `"90.00"`, и `priceSteps: 0`. Сервер сам определяет валюту: сумма меньше 500 — RUB, минимум 90; от 500 — KZT, минимум 500. Пустое поле и сумма ниже минимума блокируют отправку в приложении; сервер также проверяет минимум. Ручная цена вне настроенного города отклоняется. Количество мест умножает цену, но не меняет валюту: два места по 499 стоят 998 RUB, два по 500 — 1000 KZT.

Валюта фиксируется в заказе, ленте водителя и предложениях. Встречные предложения водителя сохраняют валюту заказа. Курс и валюта баланса фиксируются в новых заказах с этой политикой; при завершении комиссия пересчитывается в валюту баланса по сохранённому курсу, а не по последующей настройке города. Исторические суммы/валюты и балансы миграция не меняет. Старые клиенты с кнопками продолжают работать с ценой в валюте quote; новый ручной ввод доступен в обновлённой веб-версии и общем Flutter-коде для будущих мобильных сборок.

### Ручной ввод во всех городах и редактируемые минимумы

Quote возвращает `priceInputMode: "manual"`. Все пассажиры вводят `unitPrice` цифрами, `priceSteps` передаётся как 0; кнопки количества мест остаются. Без политики Байконура валюта всегда KZT, даже если валюта баланса города RUB. Минимум берётся из `cities.ride_minimum_order_kzt`, редактируется в админке «Города → город → Минимальная цена, ₸» и проверяется сервером. Значение относится к одному месту либо салону. При изменении минимума старый termsKey отклоняется; уже созданные заказы сохраняют сумму и валюту.

Для Байконура сохраняется порог 500 для определения валюты. Рублёвый минимум дополнительно редактируется в карточке города; тенговый минимум берётся из общей настройки города. Вне Байконура API не разрешает настраивать рублёвый минимум. Комиссия по заказу пересчитывается в сохранённую валюту баланса, если она отличается от валюты заказа. Предыдущие описания ручного ввода только в Байконуре и запрета ручной цены в других городах заменены этим разделом.
