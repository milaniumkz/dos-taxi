# Driver tracking and city display

Driver bonus settings remain denominated in KZT. Progress returns RUB only for Baikonur (Russian, Kazakh or English name), rounded to two decimals using the city's current KZT-per-RUB rate. Other cities return KZT. Existing wallet credit snapshots and historical bonuses are unchanged.

Both home screens and active-order screens show a small GPS city badge. It resolves an active service city using the existing booking-zone rules, refreshes once per minute and on resume, and shows an unavailable label when location or service-city detection fails. It does not infer a city from a default map coordinate or silently change the driver's configured service city.

The passenger's active-order map follows the assigned executor above the draggable order sheet for taxi, intercity and delivery. It shows road tiles and location markers without passenger navigation polylines. Each fresh GPS fix cancels interpolation toward an older fix.

`GET /orders/:id/executor-location` requires the owning passenger's JWT, an active assigned order and a location no older than two minutes. It returns no position after cancellation/completion, for unassigned orders or stale GPS. Snapshot polling every two seconds complements socket updates; driver presence supplies GPS fixes every five seconds. No messages or live orders are generated by tests.

Driver feed address rows use A and B. Passenger option/payment controls use the same yellow selected state and rounded tiles as the service selector; PSB remains restricted to Baikonur.

Only server and web publication is in scope; APK/iOS builds remain deferred.
