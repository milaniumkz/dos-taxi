# Создание тарифов и заказов в админке

Администратор, оператор и поддержка имеют одинаковый доступ ко всем операциям административного API. Клиенты и исполнители доступа к нему не имеют.

## Тариф для города

Откройте «Тарифы» → «Создать тариф» или используйте кнопку в карточке города. Выберите активный город, услугу и класс автомобиля. Валюта берётся из города, а начальные значения — из существующего тарифа, если он есть. Заполните названия на русском и казахском, стоимость подачи, километра, минуты и минимальную стоимость. Ожидание и комиссия находятся в раскрывающемся блоке.

При включении нового тарифа прежняя версия для этой услуги и класса закрывается и остаётся в истории. Новые заказы рассчитываются по новой версии; стоимость уже созданных заказов не меняется. Неактивный тариф можно сохранить без замены действующей версии.

## Заказ для клиента

Откройте «Заказы» → «Создать заказ» или кнопку в карточке города. Укажите телефон клиента; принимаются международный формат, казахстанский номер из десяти цифр и номер с префиксом 8. Существующий профиль определяется по телефону. Если профиля ещё нет, он создаётся без изменения данных других клиентов.

Выберите услугу и действующий тариф. Введите адрес отправления и назначения, нажмите «Найти адрес» и выберите подсказку. Координаты подставятся автоматически; при необходимости их можно ввести вручную. Для доставки дополнительно укажите транспорт курьера, содержимое отправления и телефон получателя. Выберите способ оплаты и добавьте комментарий водителю.

После сохранения открывается карточка заказа и начинается обычный поиск исполнителя. Заказ принадлежит указанному клиенту и доступен ему после входа по этому номеру. Поиск адресов и расчёт маршрута требуют доступных Nominatim и OSRM. Создание заказа само по себе не отправляет клиенту SMS; SMSC используется для кодов входа.

## Подключение и повторные запросы

Для сохранения нужны `ADMIN_API_URL` и серверный `ADMIN_API_TOKEN` с ролью admin, operator или support. Без подключения кнопки сохранения отключены. Интерфейс доступен на русском и казахском, введённые данные сохраняются после ошибки.

`POST /admin/tariffs` и `POST /admin/orders` требуют заголовок `X-Idempotency-Key` с UUID. Повторный запрос с тем же ключом и содержимым возвращает ранее созданную запись. Использование этого ключа с другим содержимым отклоняется. Операции записываются в журнал активности. Если заказ успел сохраниться, но дальнейший этап завершился ошибкой, повторное создание блокируется для проверки; идентификатор можно найти в `pendingOrderId` записи `order.creation_requested`.
