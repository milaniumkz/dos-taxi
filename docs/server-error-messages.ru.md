# Серверные тексты ошибок

Тексты редактируются в админке: **Настройки → Тексты ошибок** (`/settings/error-messages`). Поиск работает по коду и тексту. Для каждого кода сохраняются русский и казахский варианты. Изменение применяется сервером не позднее чем через 5 секунд, без перезапуска или деплоя. Доступ к редактированию имеет только роль `admin`.

Публичный каталог: `GET /api/v1/config/error-messages`. Ответ: `{ "version": "...", "messages": { "ru": { "TARIFF_NOT_FOUND": "..." }, "kk": { "TARIFF_NOT_FOUND": "..." } } }`. Каталог доступен до авторизации, чтобы показывать ошибки входа и сети.

Редактирование: `PUT /api/v1/admin/error-messages/TARIFF_NOT_FOUND`, заголовок `Authorization: Bearer <admin access token>`, JSON `{ "ru": "Выберите другой тариф", "kk": "Басқа тарифті таңдаңыз" }`. Обе строки обязательны, непустые, длиной до 1000 символов. Повторная отправка того же тела идемпотентна. Коды ошибок, HTTP-статусы, `details`, `traceId` и `Retry-After` сохраняются. Язык ответа определяется `Accept-Language`, по умолчанию русский.

Хранение: PostgreSQL `application_error_messages`, миграция `1710000000031`. Исходный каталог содержит все обнаруженные коды ошибок API и приложения. Для новых ошибок разработчик добавляет стабильный код и исходные переводы в `default-error-messages.ts`; дальнейшее изменение текста доступно администратору. Неизвестный код сохраняет исходное сообщение сервера. При недоступности БД сервер использует исходные переводы, а сохранение правок возвращает ошибку.

В подготовленной версии приложения каталог загружается при запуске и обновляется каждые 5 минут. Последняя корректная версия сохраняется на устройстве и используется без интернета; ошибки загрузки каталога не мешают входу и заказам. Встроенные переводы остаются запасным вариантом для первого запуска без сети.

**Установленное приложение из Play Маркета потребует одно обновление**, чтобы получать каталог для локальных ошибок и перестать показывать ложное уведомление при успешном создании заказа. После этого тексты известных ошибок меняются через админку без очередных релизов. Серверные ошибки уже получают новые сообщения без обновления старого приложения, если оно показывает поле `message` ответа API.

Причина ложного уведомления: обработчики создания и изменения статуса заказа передавали отсутствующую ошибку (`null`) в локализатор, который возвращал общий текст ошибки. Теперь отсутствие ошибки возвращает пустое сообщение, а обработчики его пропускают. Успешный заказ и обновление его статуса не считаются ошибкой.
